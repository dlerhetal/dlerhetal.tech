Moving the hub onto hosting that belongs to Top Tier

Five screens. The files are already prepared and cleaned, and a script does the work. Screen 4 is a separate errand about the other website and is not part of the move.

What this is

The deliverables hub moves onto a GitHub account with Top Tier's name on it, so that from today it does not depend on anybody outside the company.

Who runs it: Guy, or Guy's ClaudeWhere it ends up: https://top-tier-guy.github.io/How long: about ten minutes, most of it waiting

What is already done

  • The GitHub account exists. It is Top-Tier-Guy, registered to guy@toptiermn.com, a company address rather than a personal one. That was the point of setting it up that way.
  • The files are already prepared and cleaned, and they are already on this computer. They sit in the private Sandbox repository you already share, in the folder hub-site.
  • The sign in box is already gone. The hub used to ask for a Google sign in. That has been taken out of the pages and out of the program that builds them. There is nothing left for anyone to remove.

What happens next

One script does the rest. It creates a new public repository called top-tier-guy.github.io, copies the prepared files into it, pushes them, switches the website on, waits for it to answer, and then checks four things to prove it really works. It prints a plain sentence for every step.

The Sandbox repository stays private. Only the new top-tier-guy.github.io repository is public, and it holds nothing but the finished web pages that were always meant to be read. The Sandbox, with the working notes and the files you and Dale pass back and forth, is not touched and does not become public.

What you end up with

The hub at https://top-tier-guy.github.io/, hosted free by GitHub, owned by Top Tier, with no bill, no renewal and no login belonging to a consultant anywhere in it.

You are ready to start when: you are at the computer that already pushes to the Sandbox repository, and you can open a Claude session on it. That is the whole list.

One instruction to your Claude. It does everything, and it reports each thing it did as it goes.

Who: Guy, or Guy's ClaudeWhere: a Claude session on this computer

What it will print

Eight numbered steps, in this order, each with plain sentences underneath it.

StepWhat it is doing
1. Find the credentialAsks this computer for the GitHub login it already has stored. It never prints the password, not even part of it.
2. Confirm who it isChecks with GitHub that the login is Top-Tier-Guy. If it turns out to be somebody else, it stops there and says whose it is.
3. Create the repositoryMakes the new public repository top-tier-guy.github.io.
4. Assemble the filesGathers the prepared pages and reads the front page heading straight out of the file.
5. PushSends them to GitHub, and counts them on both sides to be certain nothing was dropped on the way.
6. Switch the website onTurns GitHub Pages on for that repository.
7. Wait, then prove itKeeps asking the live address until it answers, then runs four checks and marks each one pass or fail.
8. SummaryThe live address, what was done, and anything still needing a person.
Step 7 looks slow, and that is normal. After the files are pushed, GitHub builds the site before it will serve it. That usually takes one to three minutes on a first publish. The script prints a line on every attempt with how long it has been waiting, so you can see it is working rather than stuck. It gives up after ten minutes and tells you what to do next.
It is safe to run twice. If the repository already exists, it says so and carries on. If the website is already switched on, same. If the files are already there, it notices there is nothing new to send. Running it a second time is a normal thing to do, not a risk, and it is the right response to almost anything going wrong.
It worked when: the last block on your screen is headed SUMMARY, it shows the address https://top-tier-guy.github.io/, every check above it is marked PASS, and the only things listed under "Still needs a person" are to open the site and look at it. Go to screen 3 and do exactly that.

If it stops instead

It stops for only three reasons, and each one prints a sentence saying which. No credential stored on this computer: push once to the Sandbox repository so the login gets saved, then run the script again. The login belongs to somebody else: it names who, and nothing has been changed. The file count did not match: it lists exactly which file was going to be left out and refuses to publish an incomplete site. That last one is deliberate. A stylesheet has gone missing this way once before, and two pages looked wrong for days before anybody noticed.

Step 2. Only if the script says it needs a hand two minutes each

Skip this screen unless the script told you to read it. Two of the eight steps depend on what the stored GitHub login is allowed to do, and if it is not allowed to do one of them, the script prints the manual version and carries on rather than failing.

This is the exception, not the route. In the ordinary case the script does both of these itself and you never see this screen. It is here so that if the script does print one of these, you are not stuck.

Fallback A. Create the repository by hand

You need this only if the script printed "This token is not allowed to create repositories", or the same thing in GitHub's own words.

  1. Open https://github.com/new. If it asks you to sign in, sign in as Top-Tier-Guy.
  2. In the box labeled Repository name, type exactly:
The repository name, which has to be exact
top-tier-guy.github.io
  1. Leave Description empty. It does not matter either way.
  2. Click Public. This is the one choice on the page that matters. The free website only works on a public repository.
  3. Leave every tick box below unticked. No README file, no gitignore, no license. The script is about to fill the repository itself, and a starter file gets in its way.
  4. Click the green Create repository button.
  5. Go back to your Claude session and run the script again. It picks up from where it was.
It worked when: the page reloads to a screen headed Top-Tier-Guy/top-tier-guy.github.io with the word Public in a small gray outline next to the name, and a message in the middle saying the repository is empty and offering you ways to put files in it. Empty is correct. Ignore the offers.

Fallback B. Switch the website on by hand

You need this only if the script printed "This token is not allowed to switch Pages on". The files are already pushed at that point, so nothing is lost.

  1. Open https://github.com/Top-Tier-Guy/top-tier-guy.github.io/settings/pages.
  2. Find the section headed Build and deployment. Under it, the first dropdown is labeled Source. Set it to Deploy from a branch.
  3. A second row appears, labeled Branch. It has two dropdowns side by side. Set the left one to main and the right one to / (root).
  4. Click Save.
  5. Go back to your Claude session and run the script again, so that it does the waiting and the four checks for you.
It worked when: the same page redraws with a box at the top saying your site is live at https://top-tier-guy.github.io/, or saying it is ready to be published and is building. Either sentence means the setting took. The address itself may take a few minutes to start answering.
Both of these are one-time. Once the repository exists and the website is switched on, no future run of the script needs either fallback again.

Step 3. Look at it and say yes five minutes

The script has already checked the four things that are checkable from a program. What is left is the part only a person can do, which is look at it and decide it is right.

What to click and check

  1. Open the address above. The front page appears, with the Top Tier logo at the top and the heading Top Tier Roofing and Remodeling - Deliverables Hub. There is no sign in box and nothing asks you who you are.
  2. Click any three items on the front page. Each one opens. Use the browser's back button between them. Pick three different kinds if you can, one page, one spreadsheet and one PDF, so you cover more ground with the same three clicks.

  4. Open it on your phone. Send yourself the address, open it, and read one page through. Nothing should run off the side of the screen.
  5. Have somebody else open it. Send the address to Keith. The point is that it opens for a person who has never signed in to anything, on a device that has nothing set up. That is what public means here, and it is the whole reason the sign in box came out.
If a change ever seems not to have taken, wait before you fix it. GitHub serves a stored copy for a few minutes after an update, so the old version can keep appearing. Hold Ctrl and Shift and press R to force a fresh copy. If it is still the old one, wait ten minutes rather than changing anything a second time. Almost every apparent failure at this point is this and nothing else.
It is finished when: you have opened the address, three pages opened from it, it reads properly on your phone, and Keith can open it on his. At that point the hub belongs to Top Tier and runs on nobody else's account.

Changing it later

The program that builds the front page traveled with the files and sits in the new repository under generator. When you want to add something to the hub, ask your Claude to put the new file in the repository, run that program to rebuild the front page, and push. The website updates itself a minute or two later. There is no separate publishing step and nothing to switch on again.

The old address will stop working. Anything published under the consultant's own address was always temporary. Send Keith, and anybody else who has an old link, the address on this screen instead.

What Owens Corning asks for, in their own words

This is not our opinion about how your site should read. It is Owens Corning's own published guidance for contractors who display their logo, quoted directly:

"Whenever the Owens Corning logo is used in contractor material, the relationship between Owens Corning and the contractor must be established by placing 'Proud Installer of Owens Corning® Products' or 'Proud Supplier of Owens Corning® Products' above the Owens Corning logo."
"All contractor material that co-brands with Owens Corning will need to include the following legal disclaimer in addition to any promotional, technical or warranty disclaimers: (Company Name) is an independent contractor and is not an affiliate of Owens Corning Roofing and Asphalt, LLC or its affiliated companies."

Source: Owens Corning and Preferred Contractor Logo Usage Guidelines, the contractor section of Owens Corning's brand guidance. The copy read for this page is at https://chattanoogaroofingco.com/wp-content/themes/chattanoogaroofingcompany-child/pdf/MGM%20Guidelines%20for%20Contractors_100616.pdf. That is a copy another contractor has posted rather than a page on Owens Corning's own site, so if you want the current original, Owens Corning's local marketing team is the address that document itself gives for brand questions: LocalMarketing@owenscorning.com. Your Owens Corning representative can also send you the current version in a minute.

The two pieces of text, ready to copy

Both are worded for Top Tier. Use the buttons rather than retyping them, particularly the second one, which is a legal sentence where the exact words are the point.

1. The line that goes directly above the Owens Corning logo
PROUD INSTALLER OF OWENS CORNING® PRODUCTS
2. The disclaimer, for the footer or beside the logo
Top Tier Roofing and Remodeling is an independent contractor and is not an affiliate of Owens Corning Roofing and Asphalt, LLC or its affiliated companies.
Where each one goes. The first sits directly above the logo on the About page, close enough that a reader takes the two as one unit. Owens Corning's wording allows it above or below your own logo instead if the layout works better that way, but above theirs is the plain reading and it is the one to use. The second goes in the site footer, where it appears on every page, or immediately under the logo if you would rather keep it local to the About page. The footer is the tidier choice because it covers the Services page wording at the same time.

Doing it by hand in Elementor

If you would rather click it yourself, it is a text box and a footer line.

  1. Sign in at https://toptiermn.com/wp-admin/.
  2. In the left hand menu click Pages, find About in the list, and click Edit with Elementor. If you only see Edit, click that first and then the Edit with Elementor button at the top of the editor.
  3. Scroll the page preview until you can see the Owens Corning logo, and click it once so Elementor selects that element and shows its settings on the left.
  4. From the panel on the left, drag a Text Editor widget and drop it immediately above the logo. Elementor shows a blue line where the widget will land, so drop it when that line is above the logo and not below it.
  5. Delete the sample text in the new box and paste the first block from above.
  6. Set it to match the page: the same typeface as the surrounding text, centered over the logo, and a size small enough that it reads as a caption. It is a label for the logo, not a headline.
  7. Click Update at the bottom left.
  8. For the disclaimer, go back to the WordPress menu, click Templates then Theme Builder, and open your Footer. Add a Text Editor widget at the bottom of it, paste the second block, set it to the same small size as the rest of the footer text, and click Update.
The site sits behind Cloudflare, so give it a minute. Same idea as the stored copy on the hub, and for the same reason. After you save, hold Ctrl and Shift and press R on the live page, and if you still see the old version, wait rather than editing it again.

The one exemption, honestly stated

If your Owens Corning Preferred application is approved, the picture changes slightly, and it is worth knowing before you spend time on layout.

  • Verified: Owens Corning's guidance states that the Proud Installer line is not needed when using the Platinum Preferred logo. If you are displaying that badge, the badge itself establishes the relationship and the line is redundant beside it.
  • The same page also says it of the plain Preferred Contractor logo, in the same sentence. That is a genuine reading of the document, but the copy available to us is an older one hosted by another contractor rather than a current page on Owens Corning's own site, so it is worth one email to confirm before you rely on it. Ask your Owens Corning representative, or LocalMarketing@owenscorning.com, whether the Proud Installer line is required alongside the Preferred Contractor badge.
  • The disclaimer sentence is not exempted by either badge. It applies to contractor material that co-brands with Owens Corning, full stop. The only exceptions the guidance names are very small advertisements and apparel, and a website footer is neither. So add the footer sentence today regardless of where the Preferred application stands.
Which means the order to do this in is obvious. Add the footer disclaimer now, because it is required either way and takes five minutes. Add the Proud Installer line above the logo now as well, because you do not have a Preferred badge on the page today. If the application is approved and you put a badge up, that is the moment to ask whether the line still needs to sit above the plain logo.
It worked when: you open https://toptiermn.com/about/ on your phone and see the words PROUD INSTALLER OF OWENS CORNING® PRODUCTS sitting directly above the Owens Corning logo, readable without zooming in; and you scroll to the bottom of any page on the site and see the sentence naming Top Tier Roofing and Remodeling as an independent contractor. The logo itself is unchanged and the Services page wording is untouched.
