The Top Tier red

Four reds are in circulation. This says which one is right, how we know, and exactly what would change. Nothing has been changed yet.

1. The canon is settled, and not by opinion

There is a vector PDF of the compliant advertising lockup — the logo with the phone number and licence number — in the engagement files. Vector artwork stores the colour the designer typed rather than whatever a photograph of it came out as. Its colour instruction is:

CMYK  0  /  100  /  100  /  0

Solid process red: no cyan, full magenta, full yellow, no black. Converted to a screen value that is #ED1C24. That is the canon, and every other red in circulation is drift off it or a value somebody typed.

ValueWhere it livesWhat it is
#ED1C24 The vector lockup, and the 600 dpi master rendered from it CANON
#ED1B24 The mailer, business cards, review cards, locator maps One unit of green off. Comes from a JPEG copy of the logo — that shift is what lossy compression does
#EC1F25 The website, and everything we built to match the website Matches no artwork anywhere. Somebody typed it into the site
#ED1D26 The logo image the website serves WEBP compression drift
The error has a source, and it is one of our own files. assets/brand_toptier_260831.md records the primary red as #EC1F25 and says “Matches the logo.” It does not match the logo. Every deliverable built after 31 August copied that value in good faith. Fix this file first or the sweep undoes itself.
For anything printed, do not send a hex code at all. Give the printer CMYK 0/100/100/0. That is the artwork’s own instruction, it is exact, and it removes the conversion guesswork that created this mess.

The frozen bucket is not laziness, it is integrity. It holds DONE.md, the WordPress backups taken before we edited the live site, the research notes and the archive. Those are records of what things were. Editing a backup so it matches today’s brand makes it a false record and destroys the only undo this project has — there is no version control here.
