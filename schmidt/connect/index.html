2. Part 1 — SimpleFin, the Cash Pipe (start here; almost no permissions needed)

The banks hold the only numbers this engagement has verified to the penny across thirteen months. DOC SimpleFin is a read-only bank-feed protocol (“a window on a safe — it lets people look at, but not touch, your financial information” VERIFIED — simplefin.org); the Bridge is the hosted service that connects real banks to it. This is the shortest path to the first trustworthy number on the board, and it does not touch QuickBooks or ActionFlow at all.

  2. Check coverage: on the laptop, go to beta-bridge.simplefin.org/search-institutions and type the bank’s name, then “First Horizon.” The search needs a human in a browser (it would not answer an automated fetch), which is exactly what tomorrow provides. Institution search page VERIFIED to exist; these banks’ presence is what this step confirms
  3. Sign in to the Bridge account created from home in Part 0 (or create and pay for it now: bridge.simplefin.org → Get started; $1.50 + tax/mo or $15 + tax/yr; payment before connecting). beta-bridge.simplefin.org VERIFIED
  4. Diane Connect ***650 and ***922: in the Bridge, go to Financial Institutions > New Connection, pick the bank, and hand Diane the keyboard — she signs in with the bank’s online-banking credentials herself, inside the connection flow. His call, made in the room, either way in under a minute.
  7. Issue the scoreboard’s token: in the Bridge, My Accounts > Apps > New Connection generates a Setup Token (the Bridge’s own developer guide points the same flow at /simplefin/create). Copy it once — it is single-use. Actual Budget docs + beta-bridge.simplefin.org/info/developers VERIFIED
  8. Claim the token (I do this part, on the laptop — it is the whole protocol handshake): (a) Base64-decode the Setup Token; it decodes to a claim URL. (b) Send one POST to that URL with Content-Length: 0. (c) The response body is the Access URL — a URL with Basic-Auth credentials baked in. This works exactly once; the claimed token is dead afterward (reuse returns 403). The Access URL is stored on my machine only, treated as a credential — never pasted into anything public, never displayed again. simplefin.org/protocol.html + Bridge developer guide VERIFIED
  9. First pull and reconciliation: GET {ACCESS_URL}/accounts with version=2 (optionally account=… and start-date/end-date; windows limited to 90 days). The JSON carries organization info and, per account, id, name, balance, available-balance, balance-date, and a transactions array. Reconcile it account by account against the month-end balances already proven from the statement PDFs — thirteen months of those chain to the penny DOC — before the board trusts the feed. simplefin.org/protocol.html + developer guide VERIFIED
  10. Say out loud what the feed is: 24 requests or fewer per day (violations warn, then disable the token), and the Bridge refreshes each bank roughly once every 24 hours at a time of day that varies. The scoreboard’s cash number is a daily truth, not a live ticker — and the board says so on its face. Deeper history than each bank provides stays sourced from the statement PDFs already analyzed. Rate limit: Bridge developer guide VERIFIED; once-daily refresh + history caveat: Actual Budget docs VERIFIED
