Connecting the Three Systems Behind the Scoreboard

The scoreboard (“The Game”) needs three things: what each job earned, what each job cost, and what the bank actually says. Today those live in three disconnected places — ActionFlow (the shop system), QuickBooks Desktop Enterprise 24.0 (the ledger), and four bank accounts. This page is the click-by-click plan for wiring them together.

Every mechanism claim below carries an evidence label: DOC from a document already in this engagement · VERIFIED checked live on the web while writing this page · INFERENCE labelled deduction · UNCONFIRMED single or weak source · GATED the answer exists behind a login or a phone call, and the unlock path is stated. Where documentation is absent, this page says so. Nothing here is bridged with a guess.

3. Connection B — QuickBooks → The Game

The scoreboard reads the ledger two ways: the near-term path (report exports — workable today, human-powered) and the better path (the read-only ODBC driver that ships free inside Enterprise — machine-readable, no re-keying). Both are below.

Standing condition on everything from QuickBooks: the engagement’s own finding is that these records are not currently GAAP-reliable — one catch-all account holds 86% of cost of goods sold, and QuickBooks’ cash balance disagrees with thirteen months of verified bank statements. DOC The ledger feeds the scoreboard’s structure (invoices, A/R, overhead); the cash truth comes from Connection C.

3a. Near-term path — report exports, click by click

These are ordinary QuickBooks Desktop report navigation, the same convention the 7/31 setup guide used. Intuit’s first-party help pages were unreachable during research (three sessions running), so menu wording is carried from standard Desktop navigation INFERENCE — ordinary QB navigation; the on-screen menus are authoritative.

  1. Open QuickBooks Desktop Enterprise and sign in.
  2. Overhead (the scoreboard’s “Wall”): Reports > Company & Financial > Profit & Loss Standard. Set the date range to the month in play.
  3. Open balances (what the current board’s red/amber scoring runs on): Reports > Customers & Receivables > A/R Aging Detail. The current Schmidt board was built from exactly this export plus the installed-jobs listing. DOC
  4. The cost-side truth test: Reports > Accountant & Taxes > Transaction Detail by Account, filtered to the catch-all Cost of Goods Sold account. If its transactions are bills and checks with vendor names, the plug is manual coding; if they are journal entries with system memos, something is auto-posting and we chase it. Thirty seconds, settles a standing question. DOC — the register test from the ActionFlow briefing
  5. On any open report, click Excel (report toolbar) and choose Create New Worksheet — or Create Comma Separated Values (.csv) where offered — and save the file to the agreed folder.
  6. To avoid rebuilding filters every week: with the report configured, click Memorize on the report toolbar, name it, and reopen it later from Reports > Memorized Reports.

Once real job costing exists (Section 5), the same path adds Reports > Company & Financial > Profit & Loss by Job and Reports > Jobs, Time & Mileage > Job Profitability Summary — the native job-costing spine Enterprise already contains. DOC Today those reports would be empty, because nothing is job-tagged yet.

  1. Identify the primary bank by name (the UNKNOWN in the table above). One glance at a statement PDF header closes it.
  2. Check coverage: go to beta-bridge.simplefin.org/search-institutions and type the bank’s name, then “First Horizon.” The search needs a human in a browser — it would not answer an automated fetch, so coverage of our specific banks is unverified as of this writing.   3. Go to bridge.simplefin.org — it currently redirects to beta-bridge.simplefin.org (302 observed live 8/2/2026). Click Get started and create an account. Decide up front whose account this is — the credentials belong with the client (Blake or Diane), because the bank logins do. beta-bridge.simplefin.org VERIFIED
  4. Subscribe: $1.50 + tax per month, or $15.00 + tax per year, covering up to 25 institutions and 25 apps. Payment is required before accounts can be added. Price and limits: beta-bridge.simplefin.org VERIFIED; pay-before-connect: Actual Budget docs VERIFIED
  5. Connect each bank: Financial Institutions > New Connection, then sign in with that bank’s online-banking credentials in the connection flow. Repeat per institution. Whoever holds the bank logins does this step — the logins are never shared with me or with The Game. Menu names per Actual Budget setup docs VERIFIED (third-party but current)
  6. Issue a token for the scoreboard: My Accounts > Apps > New Connection generates a Setup Token (the Bridge’s own developer guide points the same flow at /simplefin/create). Copy it once — it is single-use. Actual Budget docs + beta-bridge.simplefin.org/info/developers VERIFIED
  7. The Game’s collector claims the token — this is the whole protocol handshake: (a) Base64-decode the Setup Token; it decodes to a claim URL. (b) Send one POST to that URL with Content-Length: 0. (c) The response body is the Access URL — a URL with Basic-Auth credentials baked in. This works exactly once; the claimed token is dead afterward (reuse returns 403), so the Access URL is saved securely on the collector side and never displayed again. simplefin.org/protocol.html + Bridge developer guide VERIFIED
  8. The collector then reads accounts on a schedule: GET {ACCESS_URL}/accounts with version=2, optionally account=… and start-date/end-date (windows limited to 90 days). The JSON carries the account set: organization info, each account’s id, name, balance, available-balance, balance-date, and a transactions array (id, posted, amount, description), plus an errors list. simplefin.org/protocol.html + developer guide VERIFIED
  9. Respect the service’s limits — they shape what the cash tile can promise: 24 requests or fewer per day (violations warn, then disable the token), and the Bridge refreshes each bank roughly once every 24 hours, at a time of day that varies. So the scoreboard’s cash number is a daily truth, not a live ticker — and it should say so on its face. Rate limit: Bridge developer guide VERIFIED; once-daily refresh: Actual Budget docs VERIFIED
  10. Verify: reconcile the first /accounts pull against the month-end balances already proven from the statement PDFs, account by account. Thirteen months of those balances chain to the penny DOC — the feed must tie to them before the board trusts it.

Historical depth caveat: the sync pulls at most 90 days per request window, and how far back each institution provides data varies by bank. VERIFIED Deeper history stays sourced from the statement PDFs already analyzed.

6. The Order of Operations

Sequence and dependencies only. No durations — none would be honest.

  1. One client conversation unlocks three gates at once. Ask for: (a) the ActionFlow billing screen (which tier — decides whether Connection A is licensed); (b) the support-portal login for support.actionflow.net (unlocks the vendor’s setup documentation); (c) the primary bank’s name plus Blake’s go-ahead on read-only ODBC. Everything else depends on at least one of these.
  2. SimpleFin can start in parallel with everything. Connection C depends only on the bank names and on whoever holds the bank logins — not on ActionFlow, not on the ledger cleanup. It is the shortest path to the first trustworthy number on the board.
  3. Read the vendor’s QuickBooks KB articles before configuring anything (Phase B before Phases C–D). The Desktop mechanism is unpublished; the gated articles or the support call settle it. Configuration before documentation is how systems end up half-installed — this client has lived that already. DOC
  4. Run the COGS register test before trusting any cost figure (Section 3a, step 4). Its answer decides whether the cost-side cleanup is a coding fix or a systems chase.
  5. Job-tagged cost capture is the long pole. The item-receiving and consumption procedures put material cost onto jobs going forward; labor-to-job needs the ActionFlow answer (or a timesheet process). Only after cost lands on jobs does the scoreboard’s native profit scoring switch on — before that, the board keeps its current cash-closure scoring, honestly labelled.
  6. Then rebuild the board on live feeds: ODBC (or scheduled exports) for the ledger side, the SimpleFin access URL for the cash side, ActionFlow’s registers for job identity. The board’s architecture already supports this — the static page and the live page are the same code with the transport swapped. DOC
